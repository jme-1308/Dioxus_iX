# Dioxus iX

A Rust component library porting [Siemens Industrial Experience](https://github.com/siemens/ix) to **Dioxus =0.8.0-alpha.2**, for web and desktop WebView applications.

This is an independent, early-stage port. It is not an official Siemens product. Siemens logos, corporate wordmarks, and other logo icons are excluded. The target is what iX **Brand** would be if built for Dioxus: a good visual approximation that aims to retain the upstream functionality through idiomatic Rust components, props and events. Exact internal behavior or JavaScript API compatibility is not the goal. Core workflows come first; missing capabilities and limitations remain tracked in IMPLEMENTATION.md.

## Rust-authored implementation

Component logic, behavior, state, and examples are authored in `.rs` files. Library and gallery styles and SVG assets live in bundled source files, embedded at compile time with `include_str!`; consumers need no manual asset copy, runtime asset URLs, or asset loader. Dioxus owns rendering, component lifetimes, ordinary events, native inputs/files, element measurements and mounted focus. Menus and overlays use Rust state and explicit component relationships. Custom controls use Dioxus composition or mounted-element registration. There are no JavaScript fallback paths.

Focused primary native integrations remain where the pinned Dioxus API lacks an operation or fact: dialog/popover presentation, document-wide viewport/input and focus-eligibility facts, full native validity/form metadata and text selection, chart pointer capture and SVG/PNG export/download, and target-aware desktop navigation. Rust owns their state, policy and cleanup. The private acknowledged query helper addresses a demonstrated desktop evaluation-result lifetime gap; it is not a DOM-management or focus runtime. Source comments and the [R02.62 handoff](IMPLEMENTATION.md#r0262-dioxus-gallery-history-and-ui01-discovery--2026-10-19) document these boundaries. This implementation still contains embedded JavaScript for those native integrations.

The crate does not embed the upstream ECharts, AG Grid or Web Component runtimes. Consumers do not install a separate Node/JavaScript package. Cargo builds Dioxus's platform runtime; a web build generates JavaScript glue and WebAssembly.

`Cargo.toml`, Cargo's lockfile, this README, [implementation tracking](IMPLEMENTATION.md), [LICENSE](LICENSE), and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) provide crate metadata, documentation, and required license notices. `AGENTS.md` and project-local skill instructions are approved development-tooling exceptions. They and the existing Impeccable setup are excluded from the crate package.

## Use the library

The public Rust API is in development and may change between revisions. It targets the exact Dioxus alpha version below; there is no stable-API or crate minimum-supported-Rust-version commitment. The CLI setup guidance later in this README describes the pinned development environment.

```toml
[dependencies]
dioxus = "=0.8.0-alpha.2"
dioxus-ix = { path = "../Dioxus_iX" }
```

```rust
use dioxus::prelude::*;
use dioxus_ix::*;

fn app() -> Element {
    let mut enabled = use_signal(|| false);

    rsx! {
        IxTheme { scheme: ColorScheme::System,
            Button {
                onclick: move |_| enabled.toggle(),
                "Toggle the machine"
            }
            Checkbox {
                label: "Enabled",
                checked: enabled(),
                oncheckedchange: move |value| enabled.set(value)
            }
        }
    }
}
```

Import a platform in the consuming application's Dioxus configuration. The library itself has no renderer enabled by default. Optional `web` and `desktop` features forward the matching Dioxus renderer; the `desktop` target uses the Dioxus desktop WebView renderer, not Blitz native rendering.

Each outer `IxTheme` installs the bundled styles once for its descendant theme scopes. Nested themes keep independent colors, density and token overrides while reusing those styles. Independently rooted sibling themes own separate bundles for their full lifetimes, including SSR; no global style manager or consumer asset setup is needed. Scoped overrides follow normal document CSS ordering.

`IxTheme` accepts externally supplied upstream tokens through `style` or ancestor inheritance: 23 semantic color aliases across light/dark/system schemes, font family and body shorthand, radius, and control height. Missing tokens retain provisional defaults; direct `--ix-*` values in `style` take precedence. For example, with tokens and fonts you are authorized to use:

```rust
IxTheme {
    style: "--si-sys-color-background-accent:#006b80;--si-sys-sizing-border-radius-sm:6px;--si-sys-sizing-size-90:44px;--si-ref-typography-font-family-sans:Arial;--si-sys-typography-body:normal 16px/1.5 Arial",
    Button { "Continue" }
}
```

`DateInput` and the built-in dropdown trigger consume `--ix-control-height`; `Button` keeps its own variant and density sizing recipes.

## Scope and parity

The upstream reference at port initialization is iX core `5.2.1`, commit `8bf599bc68365d7752e12832e71b625883b93d7a`. Public APIs use Rust props and events rather than JavaScript custom-element APIs.

Initial modules cover actions and status displays, forms and selection, cards and information layouts, keyed tab panels, pagination, workflow steps, date/time inputs and pickers, trees, the application shell and panes, feedback surfaces, scoped toast notifications, menus, chat, category filters, flip tiles, responsive grids, native dialogs and popovers, and an icon catalog. The Port coverage view lists 121 current custom-element tags from the pinned source, with 120 initial Rust mappings; upstream's empty internal `ix-playground` host remains unported. Mappings distinguish components, renamed APIs, item models, internal integrations, and compositions. They do not establish behavioral, visual, accessibility, or release parity. The earlier directory-based inventory was incomplete.

Deprecated `ix-menu-settings-item` and `ix-menu-about-item` components are excluded from the source's 123 declared tags. Their Rust wrappers and the menu's deprecated built-in tab props are removed; settings/about content uses explicit `TabSet` and `TabPanel` composition. The stylesheet-only `split-button-item` entry is also excluded from component counts. `SplitButtonItem` remains a current Rust configuration type for `SplitButton`, alongside item-model APIs such as `SelectOption` and `TabItem`. `UPSTREAM_EXAMPLE_NAMES` records the 256 supported, nonlegacy preview filenames from the source's 264-example inventory.

The [implementation tracker](IMPLEMENTATION.md) contains the authoritative work queue, parity ledger, verification history, and handoff. The following API notes explain current use; they do not certify complete parity.

`Input`, `Textarea`, and `NumberInput` observe native constraint validity and become touched on blur. `onvaliditystatechange` receives `ValidityStateChangeEvent` when automatic valid/invalid state changes; synchronous `prevent_default()` vetoes that feedback change. Explicit `FieldState` and feedback props remain available. A form's native `noValidate` suppresses automatic feedback; an invalid field uses its native validation message when no custom invalid text is supplied. `CustomField` aggregates validation reported through Dioxus context by library controls and `use_custom_field_state`; consumers can also pass an explicit `state`. Arbitrary descendant DOM class mutations are not observed. The Forms category's **Native field validation and methods** demonstration exposes query, focus, veto, and mount/unmount controls.

`use_input()`, `use_textarea()`, and `use_number_input()` return scoped `TextControlController` values, also named `InputController`, `TextareaController`, and `NumberInputController`. Attach one with the control's `controller` prop. Methods provide `is_touched()`, `has_valid_value()`, `get_native_input_element()`, async `focus_input()`, async `get_validity_state()`, and async `get_associated_form_element()`. `NativeValidityState` copies all native validity flags; `NativeFormElement` supplies `id`, `name`, `method`, `action`, and `no_validate`. `has_valid_value()` is a value-presence query: text must be nonempty; numbers may be empty when optional and otherwise must parse to a finite number. It is separate from native constraint validity. Errors are `TextControlError::NotMounted`, `MultipleMounted`, and `Dom`. A retained `NativeTextControl` descriptor exposes `id()`, async `focus()`, and async `set_value()`; after unmount it rejects operations. `set_value()` changes native text without dispatching application events, and controlled props remain authoritative on the next render.

`Input`, `Textarea`, and `NumberInput` also accept `onmounted: EventHandler<MountedEvent>`. The callback receives the actual native input/textarea after internal registration, so host components can retain `event.data()` and use Dioxus measurement, scrolling or async `set_focus(true)`. Keep handles in the component scope that owns the field and replace them on a new mount. The work-order example uses these callbacks for its Edit actions; no DOM query or JavaScript fallback is needed.

`NumberInput` defaults to `"0"`. Its existing string `value`/`onvaluechange` API retains editable notation, while `onnumericvaluechange` supplies `Option<f64>` on input and stepping. Empty input emits `Some(0.0)` unless `allow_empty_value_change` is enabled. `oncommit` reports the actual optional number once per changed value on Enter or blur; Enter followed by blur does not duplicate it. Blur normalizes scientific notation without emitting another value-change event. `suppress_submit_on_enter`, end/start alignment through `text_alignment_end`, min/max/step, and optional stepper buttons are supported. The separate **Numeric values and commits** demonstration exposes these states.

Dropdown arrow and Home/End navigation use explicitly registered items and current native order/eligibility facts after keyed children move, skipping disabled items and other submenus. Rust generations reject obsolete focus work; focus executes through current Dioxus mounted handles. Custom native fields register through `use_dropdown_item` or `use_dropdown_item_with_options`. The Feedback category's **Dropdown item order** demonstration reorders root and nested items without replacing their stable keys.

`Pane` maintains mutable expansion and accepts external `expanded` prop updates. User requests call `onbeforeexpandedchange` with a cancelable `PaneExpandedChangeEvent`; a veto preserves state and suppresses `onexpandedchange`. Floating panes use registered Dioxus mounted controls for autofocus, Tab/Shift+Tab boundary wrapping and eligible opener return after Close/Escape. Interior Tab keeps native traversal; inline panes do not trap it. The built-in toggle and library Button/IconButton controls register automatically. Custom fields or actions use `let mounted = use_focus_mount(id);` and attach `onmounted: mounted` to that stable-id element in a component that unmounts with it. Unregistered controls retain ordinary browser use but receive no programmatic focus or JavaScript fallback. Current native order/visibility facts exclude disabled controls, hidden mirrors and inert/hidden ancestors. Outside dismissal preserves an independent focus destination. `PaneLayout` content clicks dismiss floating panes; `close_on_click_outside` also supports outside dismissal. `aria_label_icon` and `aria_label_collapse_close_button` customize accessible names.

Pane sizing accepts the upstream size allowlist and caps desktop expansion at half the parent dimension. Collapsed tracks are 40px on desktop and 48px at the upstream 48em viewport breakpoint. At that breakpoint, left/top panes occupy the top edge and right/bottom panes the bottom edge; expanded panes overlay the full layout container. The Application category demonstrates an input and a **Keep pane open** veto while source fixtures retain their initial configuration. Pane animation, border/z-index exceptions, and the complete application-shell API remain unfinished.

`DataGrid` uses typed `DataGridColumn`, `DataGridRow`, and controlled `DataGridState` values with `onstatechange`. Configured columns support sorting, text-filter conditions, filtered multi-selection and range selection, resizing, delayed cell tooltips, and stable-ID row movement. Row virtualization is enabled by default: `row_height: 42` CSS pixels (minimum 24), `row_buffer: 10` extra rows per side, and `suppress_row_virtualisation: false`. Set that last prop to `true` to mount the full filtered dataset. The bounded DOM does not imply bounded total CPU work, an infinite dataset, or a server row model.

`DataGridState.column_order` uses stable column IDs, ignores unknown and duplicate IDs, and appends newly supplied columns in input order. Columns are `reorderable` by default, with native header drag-and-drop or Alt+Left/Right on a header control. Double-clicking a resize separator or pressing Enter on it fits the header and all filtered values, including unmounted rows, within column width limits; temporary inert Dioxus markup and a mounted measurement supply the fit. Widths, sort, filters, and selection remain tied to stable IDs when columns move. The Data grid category supplies 10,000 illustrative records: browser checks kept 18 rows mounted at both ends, fitted the long final Type value while offscreen, and retained selection through stable IDs. The two upstream grid fixtures explicitly set `suppress_cell_focus: true`; the library default is `false`.

Grid Up/Down, Home/End, and PageUp/Down reveal offscreen destinations. In cell mode, Home/End also choose the first/last column, Left/Right move between columns, Ctrl/Meta+Left/Right choose the first/last column, Tab/Shift+Tab traverse cells and leave at the dataset boundaries, and Space toggles row selection. Selection checkboxes retain row navigation when cell focus is suppressed. Row drag handles support Alt+Up/Down; separators support arrow-key resizing. It is a Rust grid with its own API; AG Grid and its JavaScript/plugin API are not embedded.

Text editing is opt-in through `DataGridColumn.editable` and `DataGridTextEditor { required, max_length }`; length counts Unicode scalar values. `DataGrid.read_only` and `DataGridRow.read_only_cells` suppress editing. Enter, F2, double-click, printable input, or Backspace starts an edit; Escape cancels and Enter commits. Tab/Shift+Tab commits and moves through editable cells in the sorted, filtered model, skipping read-only cells and revealing offscreen rows. Invalid values retain the editor with an associated alert outside the grid's scrolling clip. Accepted changes emit `oncellvaluechanged: DataGridCellValueChanged`; consumers can apply them with `apply_to`, which checks stable IDs and the original value before overwriting controlled rows. Invalid, canceled, or unchanged edits emit no change. The separate **Editable equipment register** demonstrates validation, controlled updates, read-only states, and meaningful minimum column widths with internal horizontal scrolling on mobile.

`Tabs` and `TabSet` support uncontrolled defaults and authoritative controlled selection, including explicit empty selection through `TabSelection::Empty` or `TabKeySelection::Empty`. `onbeforechange` can synchronously veto a user request before mutation; `onselectionchange` reports an optional index/key, while existing nonempty callbacks remain available. Empty selection hides all mounted panels and gives the first enabled tab a keyboard entry point. `TabPlacement::Bottom` is the default; `Top` moves the indicator edge without reordering tabs. These Rust event semantics are an adaptation: upstream mutates/emits/rolls back selection and also applies a programmatic active-key veto. See B02 for the remaining difference.

`Menu` exposes cancelable `onbeforeopensettings` and `onbeforeopenabout` requests with `MenuOpenEvent { overlay, opening }`. Toggle-open and toggle-close requests call the hook; a veto preserves state and suppresses accepted notifications. Explicit Close, Escape, and external overlay signal writes bypass those toggle hooks. Accepted actions retain `onopensettings`/`onopenabout`. Closure returns focus to the actual invoker when the overlay owned focus, preserving an already-focused external control.

`Tabs` measures overflow automatically, responding to resize, content mutation, and font loading, with observer cleanup on removal. All tabs stay in their original source order in a horizontally scrolling strip; an all-tabs menu appears on overflow except in stretched layout. `overflow_menu` can force that menu on `Tabs`. Selection reveals the chosen tab in the strip. `Tabs` and `TabSet` accept `keyboard_navigation: TabKeyboardNavigation::Automatic` (default) or `Manual`; Manual moves focus with arrows/Home/End and activates with Enter or Space. `TabSet` keeps inactive keyed `TabPanel` children mounted and hidden, preserving their local state. The `tabs-overflow` source fixture keeps all eight panels mounted.

`CategoryFilter` keeps inline options by default, matching upstream's opt-in top-layer behavior. Set `enable_top_layer: true` to use a native automatic popover anchored to the actual combobox input, escaping clipping ancestors. Placement flips and clamps to the viewport and follows scroll/resize, with listener and observer cleanup on closure/removal. Native activation errors report through `onnativeerror` and fall back to inline options. Click selection, Tab navigation from input to operator to clear (and reverse), Escape, outside dismissal, and closure on focus leaving are supported. `onbeforeclear` can cancel a reset before committed and draft state change. Source fixtures retain inline defaults; the Patterns category includes a separate clipped-container probe.

`Upload` supports `directory_upload`, `multiline`, `aria_label`, `disabled_text`, `onentrieschanged`, and `onerror`, alongside `onfileschanged`. `UploadEntry` carries a `FileData` handle and a `PathBuf` `relative_path`; `UploadError` reports selection-policy and folder-reading errors. Browser folder selections preserve relative paths. Desktop folder selections expand recursively on a worker thread, skip symbolic links, and collect metadata while deferring file-content reads. Selection allows one file by default; `multiple` or `directory_upload` permits multiple files. The native input resets so choosing the same file or folder again emits another change, and asynchronous supersession guards discard stale results. Optional `select_file_text`, `button_text`, `loading_text`, and `aria_label` strings use file/folder defaults when omitted. Loading disables selection while retaining full opacity. The Forms category demonstrates choosing folders, nested paths, and selection events; the source `upload` fixture retains its default file behavior. Browser checks selected the same folder fixture twice and preserved nested paths in both events; the desktop folder walker passed a nested-file/readability test, while the actual operating-system folder picker remains unautomated. Directory drops depend on `DataTransfer.files` and the host; there is no custom browser entry traversal or network upload service.

`CartesianChart`, `PieChart`, and `GaugeChart` provide typed Rust/SVG charts, including configured line/bar combinations, stacking, independent value axes, legends, and tooltip navigation. `ZoomChart` supports viewing-window changes and LTTB sampling, demonstrated with a 20,000-sample series. These components do not interpret ECharts options or supply an ECharts/GL engine. Weather and zoom fixtures visibly identify synthetic data. The gallery's multi-axis plots preserve a readable 760px minimum width with native horizontal scrolling on narrow screens; mobile Cartesian/pie tooltips reserve their own region.

`SurfaceChart` uses original Rust geometry, orthographic projection, and lighting calculations. Its source-oriented camera starts at yaw 40°/pitch 20°, projecting a 100-unit cube into a 151-unit vertical viewing volume; scaling follows height, preserving upstream clipping on narrow viewports. The public Brand `yelloworangeRed` visual-map stops change with light/dark appearance. Area-weighted vertex normals feed double-sided Lambert lighting with main-light angles 30°/40° and ambient intensity 0.4. Faces retain 1px wireframes, three camera-dependent grid walls, and outer axis edges. Primary drag rotates; middle, Shift, or right drag pans; wheel zoom, arrow-key rotation, +/− zoom, and Home reset are supported. Pitch is limited to −90°…90°, zoom follows the source's orthographic-size limits, and finite pan is unbounded.

Original Rust orbit state now retains rotation and orthographic zoom momentum with source-derived damping `0.8^(dt/16)` and a 50ms frame-time cap. Pan is consumed once without a damped tail. Two touch contacts apply directional pinch zoom only, matching the source's absence of two-finger translation; returning to one contact rebases its position. Pointer ownership and generation guards cancel obsolete motion on a new gesture, Escape, Home, PageUp/Down inspection, blur, data or viewport changes, and unmount. The `web-time` 1.1 clock supports web and desktop; interaction state stays in Rust. Gesture tests cover damping, pinch direction, handoff, and cancellation. Physical native multitouch/pinch remains unverified.

`SurfaceChart.height: f64` defaults to `600.0`; `show_instructions` defaults to `true`, and accessible help remains on the SVG through `aria-description` when visible help is hidden. The `echarts-special-3d` source fixture uses `height: 624.0` and `show_instructions: false` inside the source's 640px host with 16px top padding. Its exact 41 × 41 sampling has nine missing central vertices and renders 1,584 quads. Shared gesture bounds use each SVG's actual view height; ZoomChart retains its 600-unit view height. The upstream HTML requests floating `echarts-gl@2`; numeric defaults were checked against published 2.0.9 source, without embedding its engine or copying its GL/shader implementation. Rust picking tests triangle depth at the cursor and selects the nearest actual source vertex on the hit triangle. Inspection renders nine axis-pointer segments and three value labels; hovering a grid wall shows its pointer without inventing a series tooltip. PageUp/Down inspect vertices and Escape clears inspection. Rendering remains one color per quad; GPU fragment interpolation and full GL/API fidelity remain unimplemented.

`SurfaceChart`, the `ZoomChart` plot, and its overview handles use native pointer capture and stable coordinates from Dioxus-mounted HTML plot viewports, including events from SVG child targets. The borderless plot wrappers share the rendered SVG bounds, so the desktop renderer never needs an SVG measurement fallback. Dioxus resize events supply chart content widths; there is no polling loop or custom measurement JavaScript. Pointer ownership and asynchronous query epochs prevent stale replies from reviving canceled drags; Escape, pointer cancellation, and lost capture clean up the gesture. Current browser checks exercised actual pointer rotation and Home reset with the orbit implementation. Earlier ZoomChart checks verified an outside-plot pan reaching a 5.0556% window start and an overview handle reaching 100%. These are bounded gesture checks; full chart-engine fidelity remains unfinished.

`ChartToolbox` adds seven controls with Rust state: horizontal zoom brush, zoom back, restore, line/bar switching, editable tab-separated data, and PNG export. Data-view refresh validates finite numeric values atomically. Cartesian toolbox keyboard brushing and pointer capture outside the SVG were verified, along with the mobile editor's viewport cap, footer reachability, Tab wrap, inert background, and validation recovery.

`export_chart_png(element_id, pixel_ratio)` captures a mounted SVG plot and returns `ChartPng` with dimensions, a data URL, validated `bytes()`, and async `download(file_name)`. Earlier evidence recorded 640 × 600 PNG generation in Windows WebView2 and a ready state at 1063 × 600 in the web gallery; the current platform-verification boundary above still applies. Download `Ok(())` means dispatch, not a saved file. The toolbox retains an explicit native **Download PNG** link. In-app browser download monitoring timed out for both automatic and explicit-link requests, so completed browser file saving remains unverified.

`use_dropdown()` returns a scoped `DropdownHandle`; share it between an external `DropdownTrigger { dropdown: handle }` and `Dropdown { controller: handle }`. The existing built-in trigger API remains available. `DropdownPlacement` supplies eight side/start/end combinations with CSS anchor positioning and viewport flips, falling back to a centered menu when unsupported. Source fixtures use external triggers where upstream does. This is a Rust controller API, not arbitrary DOM-ID/event binding or complete upstream placement/focus parity. `DropdownSubmenu` supplies attached, compact nested menus. Linked rows open their explicitly bound controller. Nested membership follows current registered relationships, including a child added while its parent is open; closing/reopening does not freeze a child snapshot. Dropdown trigger return and live-mode trigger focus use Dioxus mounted elements. `DropdownTrigger` and linked `DropdownItem` register automatically. A custom Dioxus trigger paired through `Dropdown { controller: handle, trigger: Some(id) }` uses `let trigger = use_dropdown_trigger_binding(handle);` and attaches `onmounted: trigger.onmounted`, `onvisible: trigger.onvisible`, `onkeydown: trigger.onkeydown`, `onclick: trigger.onclick` and `..trigger.attributes()` to the same stable-id element. Dioxus renders the trigger marker and CSS anchor property, and owns click activation. An ID alone installs no event handlers or DOM metadata. Dioxus owns anchor visibility and clipping observations; scrolling or hiding an anchor dismisses its open menu unless vetoed or suppressed. Built-in, library external and linked triggers attach these handlers automatically. Ordinary Dropdown keys run through Dioxus handlers in both navigation modes. Enter/Space on a DropdownItem invokes `onitemclick`; keyboard selection of a SelectItem invokes its value callback. Compatibility `onclick` callbacks receive real pointer clicks only; keyboard actions do not fabricate MouseEvent payloads. The older `use_dropdown_trigger_mount` remains focus-only; mount-only controls supply focus registration alone; ID-only controls have no automatic activation, anchor metadata, visibility, keyboard or focus support. Dropdown triggers and inside-content clicks use Dioxus handlers, including nested controls. Ordinary content dismissal preserves native input/form defaults; `keep_open` and consumer prevention retain the surface. Header More and active overflow content also use Dioxus clicks. Document-wide outside, Escape and input-mode facts use one shared native listener set. These read-only native facts complement the explicit Dioxus inventories and relationships; they do not discover or activate arbitrary consumer controls. There is no JavaScript fallback. Registration belongs to the keyed component lifetime; removal/replacement releases its handle and obsolete focus attempts. ID-only arbitrary DOM triggers have no programmatic focus fallback. Dropdown Tab exits capture a registered Dioxus destination before dismissal callbacks and focus it through an owner-scoped effect, including vetoed dismissal. Button and IconButton register their native controls automatically. Custom outside controls register with `let mounted = use_focus_mount("destination-id");` and `onmounted: mounted` on that stable-id element, in a component that unmounts with the control. Newer focus intent, removal, replacement and document changes reject obsolete work. Unregistered outside destinations have no programmatic exit focus or JavaScript fallback. Custom nonediting item buttons can attach `use_dropdown_item(id).onkeydown` for roving navigation; editable fields leave that handler unbound to preserve editing keys.

Dioxus focus and blur events on registered item controls update Rust focus state directly. Focus cues, item active classes and active-descendant ARIA render from that state; they do not require a native focus-observation receipt. Typed triggers update automatically, including before native inventory arrives, using their explicit component relationship. A custom trigger binds `aria_activedescendant: dropdown.active_descendant()` alongside its mounted registration; the accessor returns `None` for a closed menu or roving navigation. A Select option shares its host cue, while a Category highlights its actual parent control. Linked submenu triggers show their open state and clear it on close. The library does not repaint arbitrary consumer DOM or overwrite cue attributes through JavaScript.

Library items focus and scroll through Dioxus mounted elements. A custom Dioxus button or field inside a Dropdown opts in with `let item = use_dropdown_item("custom-action");`, then uses that stable `id`, `"data-ix-roving-item": ""`, `onmounted: item.onmounted` and `tabindex: item.tabindex` on its element. Registered controls participate in opening focus in both navigation modes. Library items in externally triggered active-descendant menus use Dioxus handlers for arrow and Home/End navigation. Active-descendant mode preserves native input editing and button activation after the control receives focus. The binding renders active/inactive roving tab order through Dioxus and restores the current authored index when navigation releases it (`item.tabindex.or(Some(authored_index))` for an explicit default). `use_dropdown_item_mount` remains an opening-focus/scroll-only convenience. Opening selects the first, last or checked eligible registered control; returning from a submenu focuses its registered parent through Dioxus. Active-descendant Tab boundaries wrap through registered mounted controls; interior Tab keeps native traversal. Library Menu/Category controls register their physical button or link separately from their logical host. Dropdown publishes no generic native focus command. Unregistered DOM elements receive no programmatic item focus; there is no JavaScript fallback. Changing an element identity requires replacing its keyed component so its mounted handle is registered again.

Root `Menu` navigation and `MenuCategory` parent/child focus use their registered Dioxus mounted controls. Typed controls handle keyboard navigation directly through Dioxus in web and desktop; handled navigation stays in its owning scope. A focused bare menubar handles container navigation, while arbitrary fields keep native editing keys. Read-only observations supply current keyed/wrapped order without replaying native key/default-action transactions. Up/Down and Home/End skip disabled or hidden entries. Enter/Space inside a Category closes a collapsed flyout or toggles its expanded parent, then returns focus to that parent without activating the departing child. Newer navigation, closure, replacement and unmount cancel obsolete focus requests; a missing mounted handle has no JavaScript fallback. Category hover and focus transitions use Dioxus handlers and Rust-owned leave grace; host/flyout handoff and reentry cancel pending closure. Touch leave does not arm hover dismissal. Component teardown cancels pending work and releases its own flyout. Sibling Categories reuse the shared Rust overlay coordinator. A bounded read-only query checks focus containment after focusout because the pinned Dioxus focus event exposes no related target; it never executes focus or discovers foreign scopes. Root-local current-order facts and native popover activation remain for documented missing mounted APIs.

`MenuSettings` and `MenuAbout` autofocus their mounted Close control. Close and Escape return to the registered utility that opened the overlay; switching content keeps that invoker. Closing externally after focus moved outside preserves the independent destination. Dioxus owns this focus lifecycle, including stale-request cancellation, without a document observer or JavaScript fallback.

Every `Select` has an inline combobox input with case-insensitive substring filtering. The closed single-select input shows the selected label; multiple selection shows chips and an empty query. Typing opens the list. ArrowUp/Down wraps through enabled options and an editable Add item row; Enter commits the active row. Multiple selection keeps the list open and clears the query after a commit. Clear, Escape, Tab, and outside dismissal discard the query and restore the selected-label/empty-query display. `filterable` is retained for compatibility and no longer gates filtering. A hidden native select mirrors committed values for form submission.

Select exposes `list_header`, `hide_list_header`, `dropdown_width`, `dropdown_max_width`, `aria_label_clear`, `aria_label_add`, `all_selected_text`, `no_matches_text`, and `editable_placeholder`. `oninputchange` reports raw input independently of selection; `onixblur` reports input blur. Editable additions first call `onbeforeadd: EventHandler<SelectAddEvent>`. The event exposes `value`, `prevent_default()`, and `default_prevented()`; synchronous cancellation preserves the query, options, and selection without emitting `onadd`. Successful additions become selected and emit the post-add `onadd` notification. Multiple values use intrinsic Dioxus-mounted chip measurements and Rust fitting to show a `+N` overflow control. Its popup supports hidden-item removal, wrapping arrow-key navigation, and Escape focus return. Dioxus resize notifications update fitting, and component teardown releases mounted registrations. Optional `collapse_multiple_selection` shows one removable `All (N)` chip.

`more_items_text` defaults to `"{count} more"` for the overflow control's accessible label, replacing the first `{count}`; `remove_selected_item_text` defaults to `"Remove"` before the selected label in remove-button names. An empty required Select shows feedback after input blur unless its closest form has native `noValidate` enabled. Source value changes map to `onvaluechange`/`onvalueschange`, input changes to `oninputchange`, and blur to `onixblur`; `onbeforeadd` supplies cancelable addition and `onadd` reports successful insertion. Close-time focus return checks ownership atomically and leaves focus on another field when it has already moved there; opening retains its focus behavior.

`use_select()` returns a scoped `SelectController`, attached with `Select { controller }`. It exposes `has_valid_value()`, `is_touched()`, `get_native_input_element()`, async `focus_input()`, and async `get_associated_form_element()`. `has_valid_value()` mirrors upstream's internal **required AND nonempty** query; it is not general constraint validity. The native-input descriptor supplies `id()` and async `focus()`; a form query returns `Option<SelectFormElement>` with `id`, `name`, `method`, `action`, and `no_validate` metadata. Methods report `SelectMethodError::NotMounted`, `MultipleMounted`, or `Dom`; retained input descriptors reject use after unmount, and controller reassignment releases the previous binding. Values remain controlled through props and callbacks.

`Select` also accepts `onmounted: EventHandler<MountedEvent>`. It receives the visible native combobox after internal registration, providing a Dioxus handle for focus, measurement and scrolling. The hidden native select continues to own submitted values. Retain the handle in the field’s owning component scope and replace it on remount; the work-order example uses this for Edit asset without opening the list or submitting.

`show_text_as_tooltip` presents active feedback through `TooltipFor` in the native top layer, associated through `aria-describedby`. Hover or focus reveals it after 500ms; Escape dismisses it. Rust geometry flips and shifts the requested bottom placement to fit the viewport. The Forms category's **Select input methods and feedback tooltip** demonstration supplies focus, inspection, and mount/unmount controls; source fixtures retain their initial configuration.

`TooltipFor` uses a controller from `use_tooltip(id)` and explicitly registered Dioxus anchors from `use_tooltip_anchor(controller, anchor_id)`. Wire the binding's mounted/resize/visibility and pointer/focus/keyboard handlers to the anchor; use its `describedby(existing_tokens)` value for `aria-describedby`. Shared anchors use the same controller. Legacy `anchor_id`/`anchor_selectors` discovery is unsupported and reported through `onnativeerror`; there is no JavaScript discovery fallback. Keep the controller and tooltip ID stable for their mounted lifetime. `TooltipPlacement` supports top/right/bottom/left with Rust flipping, shifting and arrow geometry. Rust owns delays and cancellation: immediate show and 50ms hide by default, extended to 150ms hide for interactive tooltips. Dioxus mounted measurements and visibility events supply element facts, the shared native viewport stream supplies document facts, and native popover methods present the panel. The `Tooltip` wrapper composes this implementation. The Feedback category demonstrates clipped hosts, shared anchors and an interactive Rust action.

`Select` keeps inline options by default (`enable_top_layer: false`), matching upstream. Opt into `enable_top_layer: true` for a native popover anchored to the control, with a minimum control width, bottom-start placement, viewport flips and shifting, and scroll/resize tracking. Rust owns the panel and subscription lifetimes. Native activation failures report through `onnativeerror` and retain Rust-rendered inline options. Source fixtures retain inline defaults; the Forms category demonstrates a clipped host and a Reject new options toggle.

Top-layer start alignment follows the control's computed direction, aligning right edges in RTL. Width/max-width prop updates and their removal apply while open without replacing the popup. Rust combines current props, mounted element measurements, Dioxus resize/visibility events and shared viewport facts for layout. Browser checks retained popup IDs across desktop 480px → 360px sizing and mobile viewport clamping at 375px followed by a 360px cap. The Forms category includes a separate RTL/live-sizing and required-blur demonstration.

`Tree` windows the visible hierarchy by default using upstream's fixed 32px rows. Props are `virtualized: true`, `overscan: 4` extra rows per side, and `max_height: 640` (`u32` pixels); `virtualized: false` mounts the full visible hierarchy. Rust computes the viewport window from Dioxus scroll/resize events and owns row mounts and cleanup. Arrow keys, Home/End, PageUp/Down, Enter/Space, and typeahead operate across offscreen rows, revealing and focusing the destination. Rows retain `aria-level`, `aria-posinset`, and `aria-setsize`, along with selection, cascading checkboxes, lazy-load callbacks, and `render_item` hooks. Clicking a leaf's empty disclosure area selects it.

Tree and Grid offscreen focus waits for the current destination's Dioxus mount. Rust-owned request/lifetime guards reject obsolete destinations; focus and scrolling use mounted handles.

The Tree category includes 2,000 illustrative devices across 20 production lines: 2,020 rows when fully expanded in a 320px viewport. Browser checks kept 14 rows mounted at both the start and End, revealed Line 20 device 100 at scroll offset 64,320px, moved ten rows with PageUp, and exercised Home, branch collapse/re-expansion, and leaf selection. Full screen-reader and platform verification remains outstanding.

`TreeModel<T>` adds a validated flat map of `TreeModelItem<T>` entries and ordered child IDs, with a hidden synthetic root. Detached staged entries remain hidden until attached. `TreeContext` maps IDs to expansion, selection, and disabled state. `use_tree_model` creates a scoped `TreeController<T>`; `ModelTree<T>` adapts it to the existing windowed `Tree`, whose hierarchical API remains available. Controller `update`, `replace`, `append`, `remove`, and `update_data` validate transactions atomically, rejecting duplicate IDs, cycles, dangling references, and multiple parents without publishing partial changes. Context for surviving IDs is preserved. `model()` and `context()` return reactive snapshots; use `set_context` to publish an edited context.

`refresh(force)` and `mark_items_as_dirty` publish ordered, queued `TreeRefreshEvent<T>` notifications with revision, dirty IDs, force, typed removed items, and exact model/context snapshots. `ModelTree` offers `onrefresh`, `onremove`, `oncontextchange`, selection/expansion callbacks, and lazy `onload`. Its declarative `render_item` receives `TreeRenderContext<T>` with the item, visual state, index, full visible-item list, context, and controller. Typed reactive content replaces upstream retained `HTMLElement` updater/removal objects; forced refresh preserves stable DOM IDs. This is an adaptation rather than full imperative API equivalence.

```rust
use dioxus::prelude::*;
use dioxus_ix::*;

fn inventory() -> Element {
    let controller = use_tree_model(|| {
        TreeModel::new("root", [
            TreeModelItem::branch("root", String::new(), vec!["motor".into()]),
            TreeModelItem::new("motor", String::from("Motor 001")),
        ]).expect("valid inventory")
    });
    rsx! {
        Button { onclick: move |_| {
            controller.update_data("motor", |name| *name = "Motor renamed".into())
                .expect("existing motor");
        }, "Rename motor" }
        ModelTree { controller, item_label: |name: String| name, label: "Inventory" }
    }
}
```

The Tree category's **Mutable tree model** demonstration adds live append, rename, removal, refresh, restore, custom content, and simulated remote lazy children; source fixtures retain their previous behavior. Desktop/mobile browser workflows and the native probe exercised the mutable model, including removal callbacks and a stable root after forced refresh.

Bundled icons accept upstream kebab-case and camelCase aliases. Use `use_icon_registry()` and `IconRegistryProvider` for a scoped runtime `IconRegistry`; `IconDefinition` and `add_icons` support custom geometry, aliases, replacement, and removal. The `add-icons` fixture demonstrates runtime registration. Custom geometry must be trusted SVG markup: registration does not fetch external SVGs, parse data URIs, or sanitize markup.

Use `use_toast()` to create a scoped notification controller and render one `ToastContainer { controller }` for it. `controller.show(ToastOptions::new("Message"))` returns an independent handle with `close`, `pause`, `resume`, and state queries. Options support custom Rust content/actions, result callbacks, positions, and lifetime. As in upstream, the expiry bar uses the CSS animation clock and pauses on pointer hover; this port also pauses while keyboard focus is inside the toast. Timed action/loading examples use the renderer-independent `futures-timer` Rust API.

Dialogs use native HTML invoker commands through `ModalTrigger`; popovers use `PopoverTrigger`. Async `ModalHandle.open()` and `PopoverHandle.show()` provide programmatic native activation. Popover triggers support click and hover/focus modes, with a 150 ms leave delay in hover mode. `onbeforechange` receives a cancelable `PopoverChangeEvent { open, previous }` before presentation or dismissal; `onshowchanged` reports completed transitions. Click opening prefers eligible body/footer controls over header Close. Interactive popovers wrap Tab at eligible boundaries while preserving native interior navigation; nested Dropdown Tab exits to the parent’s adjacent control. Opening, trigger return and Tab boundaries use registered Dioxus mounted handles. PopoverTrigger and the built-in header Close register automatically; custom content uses `use_focus_mount(id)`, and a custom trigger uses `use_popover_trigger_mount(popover, id)`, with each mounted handler attached to its stable-id element in a component that unmounts with it. Closure restores the registered configured trigger when requested; outside dismissal preserves the independent destination. Unregistered controls receive no programmatic focus or JavaScript fallback. Popovers retain their native host and Rust child state across hide/reopen. Placement uses CSS anchors with a centered fallback; public `show()` uses native `showPopover()` without inventing an active-element trigger. Outside and Escape requests pass through the Rust coordinator, so a veto keeps the native panel presented.

ModalTrigger registers its actual Dioxus control and returns focus to the trigger that opened it. Programmatic `ModalHandle.open()` captures the currently focused registered Dioxus control before native activation; Button and IconButton register automatically, while a custom button or field uses `use_focus_mount(id)` on its stable-ID element in a component that unmounts with it. Closing restores through the mounted handle after the old dialog is removed. Removed/replaced registrations and newer dialog generations reject obsolete returns. Unregistered openers receive no library return-focus request or JavaScript fallback. Initial autofocus and modal Tab containment use the native dialog behavior.

A consuming browser/WebView must support the relevant native DOM methods, [button invoker commands](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/button#command), Popover API, and image/canvas APIs for the features it uses. Modal/popover placement uses CSS anchor positioning, with a centered fallback when unsupported; tooltips use Rust placement and native manual popovers. Dropdown backdrops are explicit nonsubmitting buttons when mounted inside forms. Renderer compilation alone does not verify runtime support in each operating system's WebView.

Date/time field and date-dropdown panels also use CSS anchor positioning with placement flips and viewport bounds when supported; otherwise they open centered in the viewport. `DateInput`, `TimeInput` and `DateTimeInput` use the shared Dropdown dialog surface. Their default-false `enable_top_layer` prop presents the picker as a native popover so it can escape clipped containers. Calendar and clock controls keep their own keyboard navigation; Escape rejects unconfirmed time edits, and Confirm/Done commits them. `CalendarLocale` provides English, German, French, and Japanese names and the five date patterns used by the upstream locale examples. It is not a general Luxon-compatible formatter; unsupported patterns return `None`, and applications can supply custom calendar labels.

`Slider` shows its current value through the shared Tooltip anchored to the moving thumb. The native top layer escapes clipped containers, placement stays within the viewport, and value changes refresh placement without continuous polling. `show_tooltip: false` disables that popup independently of validation feedback; native range keys and form submission remain unchanged.

`DateTimePicker` and `DateTimeInput` apply a time limit only on its matching minimum/maximum date when date bounds are present; interior dates retain the full day. Without date bounds, time limits apply every day. Range-selection mode ignores clock bounds, and reversed clock windows are ignored. The Date & time category's **Date-aware time constraints** demonstration separates first-day, middle-day, last-day, range, and typed-input behavior.

`DateDropdown` publishes `onrangechange` immediately when a preset is selected and leaves the calendar open. Selecting that preset again restores its viewed month/year. Calendar edits remain local until dismissal, including when the parent only listens without supplying changed props. Escape, outside dismissal, and the trigger publish the current range again, including an unchanged selection. Done produces both its explicit selection event and its close event, matching the pinned source; consumers should expect two notifications from Done. The separate **Date range notifications** demonstration exposes the event count. Create a stable handle with `use_date_dropdown()` and pass it as `DateDropdown { controller: handle.clone(), ... }`. `handle.get_date_range()` returns an owned `DateRangeChange` snapshot, including unpublished calendar edits, without publishing, dismissing or moving focus. It returns `DateDropdownError::NotMounted` when detached and `MultipleMounted` when shared by several live dropdowns; attach one handle per dropdown.
