## Updating this record

Use **Open**, **In progress**, **Blocked**, and **Done** in the queue. An in-progress task names its batch owner in the handoff; a blocked task records its dependency and next action. Done requires the stated acceptance evidence.

1. Claim one bounded batch and record its owner, scope, source contract, acceptance criteria, and affected files before editing. One chat owns the active implementation batch.
2. Preserve IDs when splitting work; use suffixes such as G05.1 and G05.2. Add concrete tasks only when supported by source or observed behavior.
3. Update affected ledger rows with implementation status, exact verification/evidence references, separate web/desktop results, and remaining limitations. Keep historical evidence identified by its original batch.
4. Mark a queue item complete only when its criteria are met. Partial work stays open with a narrower remaining gap; a fixture, mapping, build, or unit test alone is not parity proof.
5. At handoff, record changed files, validation, active processes, unresolved work, and the exact next action under [Handoff](#handoff). Preserve supporting artifacts outside disposable build output when transferring the checkout.
